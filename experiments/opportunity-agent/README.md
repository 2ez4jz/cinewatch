# CineWatch 跨场景线索验证原型

日期：2026-10-23（America/New_York）。结论：**规则与状态链路验证通过；持续发现可成交套利机会尚未验证。** 当前没有真实成交，也没有已核实可执行的真实套利机会。先保留这个实验，不继续搭平台。

本目录仅存在于独立实验分支。生产 `scripts/`、`data/`、前端、根 package.json、现有工作流全部保持原样。没有新增定时任务、没有调用原邮箱密码、没有发邮件或下单。需要 Node 24，无 npm 依赖、无 AI API 费用。

## 最短运行方法

从仓库根目录运行：

```bash
# 完全离线、可重复：6轮扫描 + 1次发送失败 + 不完整数据拒绝
node experiments/opportunity-agent/run.mjs demo

# 当前3张精确版本的真实 Scryfall 样本；再次运行使用24小时缓存
node experiments/opportunity-agent/run.mjs reference

# 只读生产快照，在实验目录建立独立的日期提醒状态
node experiments/opportunity-agent/run.mjs cinema data/showtimes.json

# 所有原项目与实验测试
npm test
npm run check
```

`demo` 生成 `.local/demo/demo-report.json` 和两个带 SIMULATION 标记的通知文件组。通知包含 `.json` 和可打开预览的 `.eml`，没有收件人，也没有连接 SMTP。报告中的 `delivered` **只表示本地文件写入成功**。

`reference` 生成 `.local/reference/references.json`。它只能证明正式 API 可以接入、精确版本可以匹配；返回的 USD/EUR 等参考价格不会送入现金价差计算，`executableOpportunities` 固定为0。

## 为什么先选本地卡牌收购价差

完整筛选、官方资料和停止条件见 [RESEARCH_ZH.md](RESEARCH_ZH.md)。卡牌有精确版本 ID、便携交付和本地现金收购出口，更适合低成本人工验证；但是目前**没有取得商家授权的双边报价数据源**。原型接受用户自行核验或经授权导出的报价，不抓登录页、不使用未确认授权的商家内部接口。

这是一个确定性线索 Agent：获取 → 适配 → 成本/证据门槛 → 状态快照 → 比较 → 去重 → 本地提醒。判断依赖证据和成本字段，不需要语言模型。

## 输入真实报价

示例 JSON 在 [fixtures/quotes-simulation.json](fixtures/quotes-simulation.json)，全部价格、商家和凭证均虚构。它可以查看字段，不能作为真实商家报价。离线固定时间重播使用 `demo`，普通 `scan` 使用当前时间，过期或未来的输入会被拒绝。

```bash
node experiments/opportunity-agent/run.mjs scan /absolute/path/to/your-authorized-quotes.json
```

真实报价须设 `simulation: false`，并提供：

- `observedAt`、`complete: true`；失效/部分抓取必须报错，不能伪造完整空结果。
- 稳定的 `offer.id`；同一货源与收购方的同一种交易持续使用同一个ID。
- 买卖双方一致的 Scryfall printing ID、语言、foil/非foil、品相，以及足够的库存/收购量。
- 双方 CAD 报价、商家、核验时间、有效期、证据链接或 `manual:` 凭证编号。
- `buy.stockConfirmed: true`；`sell.kind: confirmed_cash_quote`、`sell.confirmed: true`。
- 显式填写全部成本；未知成本不能默认为0。`leadHours` 为取得货物并交付收购方的预计小时数，退出报价必须覆盖该窗口。

`manual:` 是用户自述的核验依据，程序无法证明商家承诺有效；公开买价、确认报价也仍受最终鉴定/品相/商家接受条件约束。原型只发出待人工复核线索。

计算以整数分为单位：

```text
购入占用 = (进价×数量 + 购入运费) + 对该税基的有效税额 + 交通
估算净额 = 现金收购价×数量 - 购入占用 - 卖出手续费
           - 卖出运费 - 人工时间成本 - 损失准备
```

默认门槛：所得税前估算净额≥CAD20，净额/购入占用≥15%，购入占用≤CAD300。它们是实验参数，不是市场回报预测。购入占用不是全部现金流预算；卖出邮资和风险准备也需要现金。示例13%是演示输入，真实税率、税基和实际费用须自行核实。暂不处理换汇、进口、复杂税务与多订单运费分摊。

## 已验证的行为与限制

- 首次建立基线，不补发历史记录；当次报告仍列出门槛判断。
- 新机会入队；重复扫描不重复提醒。已通知且持续成立的机会在价格小幅变化时保持安静，关闭再出现才重新提醒。
- 失败通知保留 pending，重新扫描确认仍成立后才重试；过期、消失或改变的旧通知撤销/更新。
- 状态和 outbox 同文件原子替换，先持久化后写通知；稳定事件ID让通知文件覆盖幂等。
- 输入不完整、逆序、损坏、重复ID或来源过期时拒绝，保留上次有效状态。
- `.local/` 独立状态、命名空间、扫描锁，避免写入生产目录。进程被强制终止可能遗留 `scan.lock`；确认没有进程运行后才可删除该锁。
- 只做单机、单扫描者、少量观察项；不支持分布式调度。历史/outbox尚无自动清理，试验期结束后归档即可。
- 正式API每天缓存一次；429直接失败，不换入口、不连续重试。观察列表上限20，扩大需使用官方批量数据。

真实接入和回放证据见 [evidence](evidence)。尚未运行跨天真实机会采集，不能用模拟触发次数证明市场机会频率。没有自动抓取双边可成交报价，当前不能称为无人值守套利系统。

## 维护与下一步条件

本地计算和3个/日 API 请求几乎没有新增付费服务成本；未部署新主机。按20张卡的试验范围，代码例行检查预计每周15–30分钟；**人工报价、核验与物流预计每天20–40分钟**，这是计划假设，须记时实测。API改版另需排障，不能当作固定费用承诺。

先做14天纸面验证：10–20个精确版本，至少两个合法且允许使用的货源/现金收购报价来源，记录每次提醒能否按成本表成交、品相扣减、报价持续时间和实际工时。建议继续条件：出现≥3次独立可复核机会、至少1次小额完整现金退出，并达到每单≥CAD20、投入时间回报≥CAD25/小时的自定目标。首笔试验购入上限CAD100，总试验现金占用上限CAD300；这些是建议风险预算，尚未花钱。

如果拿不到持续、可合法使用的双边数据，或14天没有可复核机会，停止该场景。即使状态引擎可用，也没有理由继续开发通用后台、账号系统、LLM研判或付费提醒产品。
